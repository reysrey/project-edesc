# IdeaHub / KaizenBoard

Внутреннее приложение для предложений по улучшению предприятия. Backend: .NET 10, ASP.NET Core Minimal API, PostgreSQL, Clean Architecture/CQRS. Frontend: React, TypeScript, Vite.

Сводка для передачи команде: [что сделано на фронте](docs/FRONTEND_STATUS.md) и [конкретные задания для бэкенда](docs/BACKEND_HANDOFF.md).

## Локальный запуск

Нужны .NET SDK **10.0.402 или совместимый по global.json** (проверено с 10.0.404), Docker Desktop и Node.js 24 LTS.

Если PowerShell сообщает, что имя `docker` не распознано, используйте раздел «Запуск с установленным PostgreSQL без Docker». Ошибка возникает до запуска базы, когда PowerShell не может найти Docker CLI.

Из корня репозитория запустите базу:

```powershell
docker compose up -d
```

В отдельном терминале запустите API:

```powershell
dotnet run --project backend/src/Web --launch-profile http
```

Локальный API доступен на [порту 5000](http://localhost:5000/scalar). При старте API применяет миграции, добавляет базовые шаблоны и создаёт роли. Тестовые аккаунты и подразделения создаются только в Development.

В другом терминале запустите фронтенд:

```powershell
cd frontend
npm ci
npm run dev
```

Приложение: http://127.0.0.1:5173. Запросы `/api` проксируются на `http://localhost:5000`. Браузер должен открывать фронтенд, а не API. Изменить адрес API можно через `frontend/.env` по примеру `.env.example`.

## Структура

- `frontend/src/app` — приложение, маршруты, layout, тема, стили макета.
- `frontend/src/features` — сценарии авторизации, предложений, справочников, аналитики.
- `frontend/src/shared` — типизированный API, runtime-проверка контрактов, общие компоненты и форматирование.
- `backend/src/Domain` — бизнес-сущности и статусы.
- `backend/src/Application` — команды и запросы.
- `backend/src/Infrastructure` — EF Core, PostgreSQL и Identity.
- `backend/src/Web` — HTTP API.
- `backend/tests` — тесты бэкенда; `frontend/e2e` — браузерные тесты фронта.
- `docs/design/ideahub.html` — исходный HTML-макет.

Подробности архитектуры, развёртывания и проверок — в [frontend/README.md](frontend/README.md).

## Настройки безопасности при развёртывании

Передайте строку подключения в `ConnectionStrings__KaizenBoardDb` из хранилища секретов. Держите PostgreSQL в закрытой сети, а фронтенд и `/api` публикуйте под одним HTTPS origin. Локальный обратный прокси должен передавать исходный `Host` и `X-Forwarded-Proto`. Для отдельного прокси настройте доверенные адреса в ASP.NET Core. Если браузер действительно обращается к API с другого origin, добавьте его точное значение в `Cors:AllowedOrigins`.

При обновлении ранее развёрнутой БД проверьте наличие локальных seed-аккаунтов `admin@localhost` и `moderator@localhost`. Если они были созданы старой версией, отзовите их доступ и активные сессии до публикации обновления.

## Показ заказчику

### Аккаунты и данные

На свежей базе с профилем `http` API создаёт три тестовых аккаунта. Для параллельной демонстрации откройте приложение в трёх отдельных профилях браузера. Вкладки одного профиля используют общую cookie-сессию.

| Кабинет | Почта | Пароль в Development | Роль Identity |
| --- | --- | --- | --- |
| Сотрудник | `employee@localhost` | `Mvp01Demo!2026` | `User` |
| Модератор | `moderator@localhost` | `Moderator123!` | `AdminL2` |
| Руководитель | `admin@localhost` | `Admin123!` | `AdminL1` |

Аккаунты хранятся в PostgreSQL в таблице `AspNetUsers`. ASP.NET Identity хранит хеш пароля в `PasswordHash`. Роли находятся в `AspNetRoles`, назначения ролей в `AspNetUserRoles`, подразделения в `Departments`. В Docker база хранится в томе `postgres_data`. Стартовые параметры тестовых аккаунтов заданы в [ApplicationDbContextInitialiser.cs](backend/src/Infrastructure/Data/ApplicationDbContextInitialiser.cs). Повторный запуск сохраняет существующие пароли.

Из корня проекта можно посмотреть почту, подразделение и назначенные роли без чтения хешей.

```powershell
@'
SELECT u."Email", d."Name" AS department, r."Name" AS role
FROM "AspNetUsers" AS u
LEFT JOIN "Departments" AS d ON d."Id" = u."DepartmentId"
LEFT JOIN "AspNetUserRoles" AS ur ON ur."UserId" = u."Id"
LEFT JOIN "AspNetRoles" AS r ON r."Id" = ur."RoleId"
ORDER BY u."Email", r."Name";
'@ | docker compose exec -T db psql -U kaizen -d KaizenBoardDb
```

### Сценарий демонстрации

1. Выполните команды из раздела «Локальный запуск». Дождитесь строки `Now listening on` в терминале API и адреса Vite в терминале фронтенда. Откройте [приложение на порту 5173](http://127.0.0.1:5173/).
2. Войдите сотрудником, откройте шаблон «Безопасность», выберите `IT`, заполните форму и подайте предложение. `IT` — подразделение тестового модератора.
3. В кабинете модератора откройте «Входящие», передайте заявку в комиссию и введите регистрационный номер. Во вкладке «На рассмотрении» откройте её снова и выберите «Одобрить», «Отклонить» или «Вернуть на доработку». Для отклонения и возврата укажите причину. Руководитель видит комиссии всех подразделений.
4. Вернитесь в кабинет сотрудника и обновите страницу. В карточке доступны история, текущий статус и причина решения. После возврата из комиссии можно сохранить исправления и подать ту же заявку повторно с сохранением номера.
5. Для проверки поддержки откройте опубликованное предложение другого аккаунта, нажмите «Поддержать», затем «Отменить поддержку». На пустом стенде создайте дополнительную идею под руководителем через «Мои предложения».
6. В кабинете руководителя откройте «Пользователи» и отфильтруйте реестр по роли или подразделению. Затем измените переключатель в «Настройках сервиса», сохраните и обновите вкладку сотрудника. Например, при отключении доски личный список сохраняется, а чужие карточки закрываются.

Для демонстрации по видеосвязи включите показ окна браузера. Адрес `127.0.0.1` открывается на компьютере, на котором запущен сервис.

### Запуск с установленным PostgreSQL без Docker

На компьютере со стендом PostgreSQL уже распакован в `D:\front\ideahub-local\pgsql\bin`. Из корня репозитория запустите базу, API и фронтенд одной командой в PowerShell.

```powershell
cd D:\front\project-edesc
.\scripts\Start-LocalDemoApi.ps1 -PostgresBin 'D:\front\ideahub-local\pgsql\bin' -WithFrontend
```

На другом компьютере укажите путь к его каталогу PostgreSQL `bin`. Скрипт поднимает PostgreSQL на `127.0.0.1:55441`, использует базу `ideahub_demo` и сохраняет данные в `artifacts/workflow-demo/pgdata`. Эта папка сохраняется при перезапуске. Хеши тестовых аккаунтов можно найти в той же таблице `AspNetUsers`.

После сообщения `IdeaHub is ready` или `IdeaHub is already running` откройте [приложение на порту 5175](http://127.0.0.1:5175/). Повторный запуск проверяет уже работающие процессы и выдаёт тот же адрес. Логи запуска находятся в `artifacts/workflow-demo`. Если порт занят другой программой, скрипт покажет её PID. Свободные порты можно задать через `-ApiPort` и `-FrontendPort`.

Чтобы выключить стенд, выполните из корня репозитория:

```powershell
.\scripts\Stop-LocalDemo.ps1
```

Скрипт останавливает фронтенд, API и PostgreSQL. Сохранённые данные остаются в `artifacts/workflow-demo/pgdata` и снова доступны после запуска. Если при запуске указали другие порты, передайте те же `-ApiPort` и `-FrontendPort`. Если PostgreSQL установлен в другом каталоге, укажите `-PostgresBin`. Если остался запущен другой экземпляр демо-API из этой папки, PostgreSQL продолжит работать до его остановки.
