# IdeaHub

IdeaHub — внутренний сервис предложений по улучшению работы предприятия. Сотрудник подаёт идею, получает обратную связь и при необходимости отправляет доработанное предложение повторно. Модератор и руководитель рассматривают предложения в своих кабинетах.

## Возможности

| Роль | Что доступно |
| --- | --- |
| Сотрудник | Картотека шаблонов, личный список идей, сохранение черновиков, подача и повторная подача. На общей доске можно поддерживать идеи коллег. В карточке видны история и причина возврата или отклонения. |
| Модератор | Очереди своего подразделения, первичная проверка и решения комиссии. Предложение можно одобрить, отклонить или вернуть на доработку. |
| Руководитель | Очереди по всем подразделениям, решения комиссии, реестр сотрудников, справочники и экспорт. В настройках сервиса управляет общей доской, поддержкой, анонимной подачей и уведомлениями. |

После возврата автор редактирует и повторно подаёт ту же карточку. При повторной передаче в комиссию сохраняется регистрационный номер, а решения остаются в истории.

## Локальный запуск

### Windows с установленным PostgreSQL

Нужны .NET SDK 10.0.402 или совместимый по `global.json`, Node.js 24 и PostgreSQL 16. Выполните из корня репозитория, подставив путь к каталогу `bin` своей установки PostgreSQL.

```powershell
.scripts\Start-LocalDemoApi.ps1 -PostgresBin 'C:\Program Files\PostgreSQL\16\bin' -WithFrontend
```

Когда появится `IdeaHub is ready` или `IdeaHub is already running`, откройте [IdeaHub](http://127.0.0.1:5175/). API слушает порт `5501`, PostgreSQL — `55441`. При необходимости скрипт установит зависимости фронтенда через `npm ci`. Docker для этого способа не нужен.

Для остановки выполните:

```powershell
.scripts\Stop-LocalDemo.ps1 -PostgresBin 'C:\Program Files\PostgreSQL\16\bin'
```

Предложения, настройки и аккаунты сохраняются в `artifacts/workflow-demo/pgdata`. Логи запуска находятся в `artifacts/workflow-demo`. Если порт API или фронтенда занят, укажите свободные порты через `-ApiPort` и `-FrontendPort`. При остановке передайте те же значения.

### Запуск с Docker для PostgreSQL

Для этого способа нужны запущенный Docker, .NET SDK и Node.js. Из корня репозитория запустите PostgreSQL, затем API:

```powershell
docker compose up -d db
dotnet run --project backend/src/Web --launch-profile http
```

Во втором терминале запустите фронтенд:

```powershell
cd frontend
npm ci
npm run dev
```

Фронтенд доступен на [порту 5173](http://127.0.0.1:5173/), API и документация Scalar — на [порту 5000](http://localhost:5000/scalar). Адрес API для Vite задаётся в `frontend/.env` по примеру [.env.example](frontend/.env.example). Данные PostgreSQL хранятся в томе `postgres_data`.

## Локальные учётные записи

При запуске API применяет миграции и загружает базовые шаблоны. В режиме Development на новой базе создаются три тестовые учётные записи.

| Роль | Почта | Пароль |
| --- | --- | --- |
| Сотрудник | `employee@localhost` | `Mvp01Demo!2026` |
| Модератор | `moderator@localhost` | `Moderator123!` |
| Руководитель | `admin@localhost` | `Admin123!` |

Тестовый модератор видит предложения подразделения `IT`. Для одновременной работы под разными ролями используйте отдельные профили браузера. Вкладки одного профиля используют общую сессию.

Аккаунты хранятся в PostgreSQL в таблице `AspNetUsers`, роли и назначения — в `AspNetRoles` и `AspNetUserRoles`. ASP.NET Identity хранит хеши паролей в `PasswordHash`. Подразделения находятся в `Departments`. Стартовые данные описаны в [ApplicationDbContextInitialiser.cs](backend/src/Infrastructure/Data/ApplicationDbContextInitialiser.cs).

## Разработка

- Бэкенд — .NET 10, ASP.NET Core Minimal API, EF Core и PostgreSQL. Исходники в `backend/src`, тесты в `backend/tests`, миграции в `backend/src/Infrastructure/Migrations`.
- Фронтенд — React, TypeScript и Vite. Исходники в `frontend/src`, браузерные тесты в `frontend/e2e`. [Документация фронтенда](frontend/README.md)
- Форматы запросов и ответов описаны в [документации API](docs/BACKEND_HANDOFF.md).

Из корня репозитория запустите тесты бэкенда. Функциональные тесты используют PostgreSQL через Testcontainers и требуют запущенный Docker.

```powershell
dotnet test KaizenBoard.slnx -c Release
```

Из каталога `frontend` запустите сборку, линтер, проверку формата и браузерные тесты. Установку Chromium выполните при первом прогоне.

```powershell
npm ci
npx playwright install chromium
npm run check
```

### Настройки развёртывания

Передайте строку подключения через `ConnectionStrings__KaizenBoardDb` из хранилища секретов. Держите PostgreSQL в закрытой сети и публикуйте фронтенд и `/api` по одному HTTPS origin. Обратный прокси должен передавать исходный `Host` и `X-Forwarded-Proto`. Для отдельного прокси настройте доверенные адреса в ASP.NET Core. Если фронтенд обращается к API с другого origin, добавьте его точный адрес в `Cors:AllowedOrigins`.

При обновлении ранее развёрнутой базы проверьте старые тестовые учётные записи с доменом `@localhost`. Если они были созданы в рабочей базе, отзовите их доступ и активные сессии до публикации обновления.
