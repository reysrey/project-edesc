# Состояние фронтенда IdeaHub

Сверено 23 ноября 2026 по коду `94df282` в ветке `codex/ideahub-frontend` и работающему OpenAPI. Новые серверные операции в рамках этой сверки не реализовывались.

## Работает с текущим API

| Область | Сделано | Практические границы |
| --- | --- | --- |
| Архитектура | React + TypeScript strict + Vite; app/features/shared; маршруты, отдельный API-транспорт, Zod-проверка DTO, TanStack Query | Сервер — существующий ASP.NET Core, SSR не используется |
| Авторизация | Cookie-вход, регистрация по почте/паролю, выход, восстановление сессии через `/Users/me`, обработка 401/403 и очистка кэша | Регистрация пока не сохраняет ФИО/должность; Identity не назначает User автоматически |
| Роли | Сотрудник; модератор `AdminL2`; руководитель `AdminL1`; разные кабинеты и меню | Клиентские ограничения не заменяют серверные проверки |
| Сотрудник | Кабинет, шесть направлений макета, реальные шаблоны, доска карточек, форма новой идеи | Общий список нельзя считать личным; «Мои предложения» явно недоступны |
| Подача идеи | Реальные POST создания черновика и submit; поля title/currentFlaws/proposedSolution/improvementObject/targetDepartmentId | Нет API редактирования и полного просмотра сохранённого черновика |
| Незавершённая форма | Восстановление текста в той же вкладке, под ID пользователя; сохранение полученного ID при неудачном submit | Это sessionStorage, не облачная синхронизация. Если ответ create потерян до получения ID, клиент не может гарантировать отсутствие дубля без серверной идемпотентности |
| Модерация | Четыре очереди, передача Submitted в комиссию с номером, возврат с причиной | Получить текст причины обратно в карточке пока нельзя: API списка его не возвращает |
| Списки | Поиск по названию/ID, сортировка, статусы, счётчики, 10/20/50/100 строк, фильтры/страница в URL | Фильтрация и пагинация выполняются локально над полным массивом |
| Подразделения | Просмотр, поиск, создание, изменение названия/численности, удаление с подтверждением | Выбор модератора недоступен без списка пользователей; действующий HeadUserId сохраняется при редактировании |
| Шаблоны | Просмотр, поиск по названию/объекту, фильтр типа, создание, изменение, архивирование; подстановка подсказок в форму | Связь TemplateId не сохраняется командой создания идеи; просмотр архива отсутствует |
| Руководитель | Обзор, количества по статусам, доля внедрённых, списки последних/внедрённых идей | Нет финансовой аналитики, фактического результата и разбивки по подразделениям |
| Экспорт | CSV с выбранными из доступных колонок; выгрузка всей отфильтрованной очереди, включая все страницы; экранирование формул | Реально доступны ID, название, статус и дата; остальные колонки отключены |
| UI | Адаптивность, светлая/тёмная тема, модальные окна, загрузка/ошибки/пустые состояния, SVG-иконки и исправленный контраст | Сохранён исходный визуальный язык HTML-макета |

Команды управления справочниками и экспорт доступны в интерфейсе руководителя. Чтение шаблонов/подразделений остаётся доступным авторизованным пользователям по прямым маршрутам; это соответствует текущим GET endpoint-ам. Модератор видит в меню только четыре очереди. Основные изменения C# за всю работу — добавленный GET `/api/Users/me`; полноценный новый бэкенд не создавался.

## Экраны подготовлены, сохранение заблокировано серверными пробелами

- **Поддержать:** одна SVG-кнопка, остальные реакции удалены; нет API — нет фиктивного счётчика/голоса.
- **Карточка:** реальные название/ID/дата/статус; текст проблемы, решения, автор, комментарии, история и финансовые данные недоступны.
- **Мои предложения:** раздел присутствует, личные записи не подменяются общим списком.
- **Комиссия и внедрение:** показаны ограничения; недоступные переходы не записываются в браузерное хранилище.
- **Ожидаемый эффект, фото и анонимность:** элементы формы отключены, потому что текущий create DTO их не принимает.
- **Пользователи:** собственный профиль из `/me`; список, смена ролей и блокировка отключены.
- **Настройка формы:** показан текущий фиксированный состав полей; изменение и общее сохранение недоступны.
- **Оформление:** работает локальный предпросмотр названия/цвета/шрифта/логотипа/паттерна, проверяется размер/тип изображения; общие настройки не сохраняются.
- **Настройки сервиса и уведомления:** экраны/пояснения есть, серверное состояние не имитируется.
- **Восстановление пароля:** форма и вызовы существующих Identity endpoint-ов есть; фактическая доставка писем не подтверждена. 2FA и управление почтой/паролем через `/manage/info` уже есть на сервере, но соответствующие дополнительные экраны не входили в текущий макет и не подключены.

## Проверки

Последняя проверка реализации: `npm run check` — сборка, линтер, форматирование, **40 браузерных проверок** на desktop/mobile. Проверяются обычные сценарии, роли, повтор submit без второй записи после получения ID, фильтры/CSV, темы, SVG и контраст выбранных элементов. Клиентские тесты используют заданные ответы API.

Отдельно ранее проверены реальные cookie-сессии трёх ролей с PostgreSQL: регистрация/вход, создание идеи, отправка, одобрение/возврат модерацией, обновление статуса, CSV и выход. Сборка .NET прошла без ошибок, имеющиеся 6 модульных тестов прошли. В Application.FunctionalTests пока нет обнаруживаемых тестовых сценариев. Эти результаты не означают, что завершён весь бизнес-процесс или проверены все серверные права.
