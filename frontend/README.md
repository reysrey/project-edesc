# IdeaHub frontend

TypeScript (strict), React, Vite, React Router, TanStack Query, Zod. Это SPA для существующего ASP.NET API: бизнес-логика и права остаются на сервере. SSR для внутреннего авторизованного интерфейса не требуется. Выбор Vite как инструмента сборки соответствует [руководству React](https://react.dev/learn/build-a-react-app-from-scratch); требования окружения — в [документации Vite](https://vite.dev/guide/).

## Запуск и проверки

```powershell
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Бэкенд запускается отдельно, инструкции в корневом README. При недоступном API приложение показывает ошибку и возможность повтора; подстановка демоданных отсутствует.

```powershell
npm run build
npm run lint
npx playwright install chromium
npm run test:e2e
```

`npm run check` выполняет сборку, линтер, проверку форматирования и браузерные тесты. `npm run format` форматирует код. Playwright проверяет desktop Chromium и мобильный viewport Pixel 7. API перехватывается только внутри тестов; проверяются вход/выход, сессия, роли, форма и повтор отправки, решения руководителя, справочники, контракты, фильтры, тема и отсутствие горизонтального переполнения. Скриншоты и trace находятся в test-results и не коммитятся. Проверка C# требует установленного .NET SDK.

## Архитектура

```text
src/
  app/                 маршруты, layout, провайдеры темы и стили
  features/
    auth/              Identity-вход, регистрация, восстановление, профиль
    suggestions/       обзор, список, карточка, создание, решения модерации
    catalog/           подразделения и шаблоны
    analytics/         экспорт выбранных полей и отфильтрованных записей
    management/        обзор руководителя, эффективность, экраны настроек
  shared/
    api/               транспорт, схемы Zod, DTO и endpoint-адаптеры
    ui/                модальное окно, загрузка, ошибки, пустые состояния
    lib/               даты и безопасное CSV-экранирование
```

Зависимости направлены от приложения/сценариев к shared. Прямые fetch-вызовы находятся только в API-транспорте; серверное состояние хранится в TanStack Query, состояние формы — внутри формы, поиск/сортировка/страница — в URL списка. При изменениях инвалидируются соответствующие запросы. При выходе или 401 очищается пользовательский кэш. Запросы GET получают AbortSignal. Мутации автоматически не повторяются.

Роли приходят из `/api/Users/me`, их нельзя выбрать в интерфейсе. AdminL1 отображается как руководитель, AdminL2 — как модератор. Первичная модерация доступна обеим ролям; управление справочниками, экспорт и настройки — руководителю. Маршруты интерфейса защищены соответствующими проверками. Окончательные права обязан проверять сервер; задачи и матрица описаны в BACKEND_HANDOFF.md.

Данные API проверяются Zod во время выполнения: неизвестные статусы и несовместимые DTO вызывают понятную ошибку. Числовые enum не поддерживаются, поскольку сервер настроен отдавать строки. Ошибки ProblemDetails и ошибки отдельных полей выводятся пользователю. Список пока фильтруется и делится на страницы локально, потому что API возвращает целый массив.

Создание идеи — POST (возвращает ID черновика), затем отдельный submit. Если submit упал, форма запоминает ID и повторяет только submit. При ошибке submit ID черновика восстанавливается вместе с формой в той же вкладке. После обычного сохранения черновика отдельное редактирование/повторная отправка из списка требуют серверного контракта с автором и проверкой владельца. Подсказки шаблона не подставляются как будто пользователь уже написал текст.

## Дизайн

Основа `app/design.css` извлечена из предоставленного HTML без исполнения его скриптов. `app/styles.css` адаптирует элементы для React и компонентов. Сохранены палитра, карточки, баннер, шрифты, светлая/тёмная тема и адаптивность. В localStorage хранится тема. sessionStorage используется только для незавершённой формы в текущей вкладке, под ID текущего пользователя. Общие настройки предприятия и голоса в браузерное хранилище не записываются. Google Fonts загружаются извне с системным fallback.

Модальные окна используют нативный dialog: удержание фокуса, Escape, возврат фокуса и блокировка прокрутки. Во время сохранения закрытие и повторное действие блокируются. Формы имеют label и native validation; уведомления об ошибках — role=alert.

## Production

```powershell
npm run build
```

Результат — `dist/`. Публикуйте статику за HTTPS на том же origin, что и `/api`. Настройте fallback SPA на `index.html` для `/suggestions`, `/templates` и других маршрутов, но не для `/api`: неизвестный API URL должен остаться ошибкой API. Пример Nginx — `nginx.example.conf`; замените upstream на реальный адрес сервера. `API_PROXY_TARGET` применяется только к Vite dev, не в production. `vite preview` сам по себе не является production reverse proxy для API.

Cookie-аутентификация: `credentials: include`, login с `useCookies=true`, logout с `{}`. Пароли и access/refresh token в браузерное хранилище не записываются. Same-origin упрощает CORS; политику CSRF и параметры cookie должен подтвердить бэкенд. Не включайте HTML-деморежим в рабочее приложение.

## Дальнейшие контракты

Полный список ограничений и задач для бэкенда: [BACKEND_HANDOFF.md](../docs/BACKEND_HANDOFF.md). Без согласованных API недоступны сохранение фото, единственная реакция «Поддержать», анонимность, история, уведомления, действия комиссии, управление пользователями и общее сохранение брендинга/настроек. Их элементы и экраны из макета отображаются с пояснениями и отключёнными действиями; оформление имеет только живой предпросмотр. Это ограничения интеграции, а не скрытый localStorage-мок.

## Иконки и контраст

Шаблоны, статусы и кнопка поддержки используют SVG-иконки из `public/ideahub-icons.svg` через общий компонент `shared/ui/Icon.tsx`. У шести направлений разные значки; для шаблона без распознанного направления предусмотрена иконка документа. Статус выводит один SVG, автоматические CSS-псевдоиконки из исходного макета отключены.

Читаемые цвета обеих тем определены в `app/accessibility.css`. Фирменный фон и цвет текста разделены: светлый фирменный цвет получает тёмную надпись, акцентный текст корректируется под поверхность. Изображение предпросмотра не перекрывает сплошную подложку текста баннера.

HTML-макет содержит встроенные копии SVG-спрайта и этих правил. После изменения общих SVG/CSS синхронизируйте его из корня репозитория:

```powershell
node scripts/sync-design-assets.mjs
```

`e2e/design.spec.ts` проверяет обе темы, desktop/mobile, реальные SVG-контуры, отсутствие дублирующих псевдоиконок, контраст проверяемых подписей не ниже 4,5:1 и светлые/тёмные фирменные цвета с изображением. Полный набор: 40 браузерных проверок.
